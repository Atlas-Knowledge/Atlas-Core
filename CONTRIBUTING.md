# Contributing to Atlas

> Thank you for your interest in contributing to Atlas.

Atlas is a long-term, standards-driven project dedicated to building trustworthy knowledge infrastructure.

Every contribution—whether documentation, code, design, discussion, or review—helps strengthen the ecosystem.

---

# Before You Start

Before contributing, please read:

1. README.md
2. MISSION.md
3. VISION.md
4. PRINCIPLES.md
5. ARCHITECTURE.md
6. GOVERNANCE.md

Understanding the architecture and governance model is essential before proposing changes.

---

# Ways to Contribute

Contributions are welcome in many forms, including:

- Documentation improvements
- Bug reports
- Feature proposals
- Standards discussions
- Architecture reviews
- Reference implementations
- Developer tooling
- Test suites

Not every contribution requires writing code.

---

# Contribution Principles

All contributions should follow the Atlas principles:

- Evidence before assumptions
- Standards before implementations
- Transparency over certainty
- Quality over quantity
- Long-term sustainability
- Respectful collaboration

---

# Contribution Workflow

Every significant contribution follows this process:

```
Idea
  │
  ▼
Discussion
  │
  ▼
Issue
  │
  ▼
RFC (if required)
  │
  ▼
Implementation
  │
  ▼
Review
  │
  ▼
Merge
```

---

# Pull Requests

Please ensure that your Pull Request:

- Has a clear purpose.
- Is focused on a single topic.
- Includes documentation updates when applicable.
- Passes all automated checks.
- References related issues or RFCs.

Small, focused pull requests are preferred over large, unrelated changes.

---

# Commit Messages

Atlas follows a conventional commit style.

Examples:

```
feat(core): add governance metadata

docs(readme): improve quick start guide

fix(kernel): correct entity validation

refactor(architecture): simplify repository model
```

---

# Coding Standards

When contributing code:

- Follow project formatting rules.
- Prefer readability over cleverness.
- Keep functions focused.
- Write documentation for public APIs.
- Add tests where appropriate.

---

# Documentation Standards

Documentation should be:

- Accurate
- Concise
- Consistent
- Version-aware
- Easy to navigate

Documentation is treated as a first-class deliverable.

---

# Architecture Changes

Major architectural changes require:

- RFC
- Architecture review
- ADR (if accepted)

Please avoid implementing architectural changes without prior discussion.

---

# Code Review

Reviews focus on:

- Correctness
- Maintainability
- Simplicity
- Documentation
- Alignment with Atlas principles

Reviews are collaborative, not adversarial.

---

# Community Expectations

Please follow the project's Code of Conduct.

Treat contributors with professionalism, respect, and empathy.

---

# Questions

If you are unsure where to start:

- Read the documentation.
- Search existing issues.
- Ask questions before implementing large changes.

We are happy to help new contributors.

---

# Thank You

Atlas exists because of its contributors.

Every thoughtful contribution helps build a stronger ecosystem for everyone.

---

> Build openly. Collaborate respectfully. Improve continuously.
